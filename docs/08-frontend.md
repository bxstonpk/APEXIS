# 8. Frontend

`apps/frontend` — Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4

## 8.1 กติกา

| กติกา | ทำอย่างไร |
|---|---|
| **ทุกอย่างเป็น component** | หน้า (page) ประกอบจาก component; feature component (เช่น `LoginForm`) ไม่ผูกกับ router / layout จึง embed ที่อื่นได้ |
| **server / client แยกชัด** | หน้า (`page.tsx`) เป็น server component เป็นค่าเริ่มต้น; component ที่มี state / event ใส่ `'use client'`; โค้ดที่แตะ cookie / token อยู่ใน `src/lib/server/` เท่านั้น |
| **ข้อความทั้งหมดอยู่ใน config** | ปุ่ม, label, placeholder, คำอธิบาย, ข้อความ error, ชื่อแท็บ — อยู่ที่ `src/config/locales/th.ts` ที่เดียว ห้ามเขียนข้อความที่ผู้ใช้เห็นลงใน component |
| **CSS ใช้ Tailwind เท่านั้น** | component ใช้ utility class; ไม่มีไฟล์ CSS ของ component |
| **สี / ฟอนต์ / เงา เป็น token** | อยู่ใน `@theme` ของ `src/styles/app.css` ที่เดียว — Tailwind สร้าง class ให้ เช่น `bg-primary`, `text-ink-muted`, `shadow-card` |
| **แนวทางหน้าตา** | สีจากโลโก้ (กรมท่า `primary` + ส้ม `accent`), พื้นเรียบ เส้นบาง เงาน้อย, ขนาดกระชับแบบโปรแกรมทำงาน (ช่องกรอก / ปุ่มสูง 40px, แถวตาราง 48px), มุมโค้ง `--radius-control` 6px / `--radius-panel` 10px; แท็บของแอปใช้แถบบนสีเข้ม `nav` |
| **การเข้าถึง (a11y)** | ช่องบังคับมี `*` (อยู่นอก `<label>` — ชื่อช่องไม่เปลี่ยน) + `aria-required`; ส่งฟอร์มไม่ผ่านโฟกัสช่องแรกที่ผิด (`focusFirstInvalid`); ลิงก์ "ข้ามไปเนื้อหาหลัก" ไป `#main`; ข้อความทุกสี contrast ≥ 4.5:1; รองรับ `prefers-reduced-motion`; ช่องกรอก 16px บนมือถือ (iOS ไม่ซูม); `scroll-padding` กันแถบ sticky บังช่องที่โฟกัส |
| **ฟอนต์** | IBM Plex Sans Thai (ไทย + ละติน) self-hosted ผ่าน `@fontsource` — โหลดใน `app/layout.tsx` เฉพาะน้ำหนัก 400 / 500 / 600 |
| **ค่าตั้งของแอป** | path ของ API / หน้า, ชื่อ query parameter, ชื่อ cookie อยู่ที่ `src/config/app.ts`; ที่อยู่ backend อยู่ใน env `APEXIS_API_URL` (ฝั่ง server เท่านั้น) |
| **โลโก้ / ภาพแบรนด์** | `src/config/brand.ts` ที่เดียว (alt text อยู่ใน `texts.app.logoAlt`) |
| **การค้นหาใช้ URL query** | หน้าใดที่มีการค้นหาเก็บเงื่อนไขไว้ใน URL แล้วส่งต่อให้ API ตรงๆ (ดู [04-api.md §4.2](04-api.md)) — login พากลับหน้าเดิมพร้อม query ผ่าน `?redirect=` |

## 8.4 หน้า login

- `/login` — ฟอร์มอีเมล + รหัสผ่าน (ปุ่มแสดง / ซ่อนรหัสผ่าน)
- ตรวจช่องว่าง / รูปแบบอีเมลก่อนส่ง (ไม่เรียก API) แล้ว focus ช่องที่ผิด
- เรียก `POST /api/session` (route handler ของ Next) → ส่งต่อไป backend `POST /api/v1/auth/tokens`
  - สำเร็จ: Next เก็บ token ใน cookie `apexis_session` แล้วตอบเฉพาะข้อมูลผู้ใช้ — browser ไม่เห็น token
    แล้วไปหน้าเดิมจาก `?redirect=` (รับเฉพาะ path ภายในแอป กัน open redirect) หรือหน้าหลัก
  - ผิดพลาด: แสดงข้อความจาก `texts.errors[error.code]` (ไม่รู้จัก = `unknown`), ล้างช่องรหัสผ่าน
- ออกจากระบบ: `DELETE /api/session` (ลบ cookie)
- เข้าถึงได้ (a11y): label ผูก input, `aria-invalid` / `aria-describedby`, error แจ้งด้วย `role="alert"`

### session / การเรียก API

```text
browser --(cookie apexis_session)--> Next server --(Authorization: Bearer <token>)--> backend Go
        /api/session                                /api/v1/auth/tokens
        /api/v1/*  -------------------------------> /api/v1/*
```

- cookie: `HttpOnly` (JavaScript อ่านไม่ได้ — กันขโมย token ผ่าน XSS), `SameSite=Lax`, `Secure` เมื่อ production, หมดอายุพร้อม token
  - ค่า = base64url ของ JSON `{token, expiresAt, user}` (ไม่ได้เข้ารหัส — ความปลอดภัยมาจาก HttpOnly และ backend ตรวจ token เอง)
- `proxy.ts`: ไม่มี session / หมดอายุ / cookie เสีย → `/login?redirect=<หน้าเดิม + query>`
- `/api/v1/*`: ส่งต่อ method, query, body, header `accept` / `content-type` / `accept-language` — ไม่ส่ง cookie ของ Next ไป backend
  - backend ตอบ 401 → ลบ cookie (ครั้งถัดไป proxy พาไป login)
  - backend ล่ม → 502 `network_error`
- กัน CSRF: คำขอที่เปลี่ยนข้อมูล (POST / PUT / PATCH / DELETE) ต้องมี `Origin` ตรงกับแอป (ไม่มี Origin ใช้ `Sec-Fetch-Site`) ไม่ตรง = 403 `permission_denied`
- component ฝั่ง client เรียก `apiRequest('/companies?...')` → `/api/v1/companies?...` ตามปกติ ไม่ต้องจัดการ token

## 8.5 หน้ารวมแอป (แบบ app launcher)

```text
/  ──>  บริษัทที่เปิดล่าสุด (cookie apexis_company) หรือบริษัทเดียว ──> /c/{companyId}
   └─>  นอกนั้น ──> /companies (เลือก / ค้นหา / สร้างบริษัท)

/c/{companyId}                 หน้ารวมแอป: ไอคอนแอปกลางจอ (เฉพาะแอปที่มีสิทธิ์)
  │  กดไอคอน = window.open(url, "apexis-{companyId}-{app}") — แท็บใหม่ ชื่อแท็บต่อแอป
  ▼                              (กดแอปเดิมซ้ำ = กลับไปแท็บเดิม ไม่เปิดซ้ำ)
/c/{companyId}/{app}/{menu}    แท็บของแอป: [✕] [ไอคอน ชื่อแอป] [เมนูของแอป ...] [ชื่อบริษัท]
     ✕ = window.close() กลับไปแท็บหน้ารวมแอป
         (แท็บที่เปิดเอง เช่น พิมพ์ URL / bookmark ปิดด้วย script ไม่ได้ -> ไปหน้ารวมแอปในแท็บนั้นแทน)
```

- แอป / เมนู / สิทธิ์อยู่ที่ `src/config/apps.ts` ที่เดียว, ชื่ออยู่ที่ `texts.apps`, สีไอคอนเป็น token `--color-app-*`
  - เมนูแสดงเมื่อมีสิทธิ์ `permission` ของเมนู (ตรวจแบบเดียวกับ backend: `*`, `sales.*:read`, `sales.order:*`)
  - แอปแสดงเมื่อเหลืออย่างน้อยหนึ่งเมนู; หน้าแรกของแอป = เมนูแรกที่มีสิทธิ์
  - ซ่อนเมนูเพื่อความสะดวกเท่านั้น — backend ตรวจสิทธิ์ทุกคำขอเสมอ
  - **ตามประเภทธุรกิจ:** `AppDefinition.businessTypes` = ประเภทที่ใช้แอปนั้น (ไม่ระบุ = ทุกประเภท) — `visibleApps(permissions, businessType)` / `appAvailableFor(app, type)`
    - คลังสินค้า: ซื้อขาย / ผลิต / ก่อสร้าง (ธุรกิจบริการไม่เห็น)
    - การผลิต (`manufacturing`): เฉพาะธุรกิจผลิตสินค้า; โครงการก่อสร้าง (construction) จะเพิ่มแบบเดียวกันพร้อม `businessTypes` ของตัวเอง
    - เปิดแอปที่ไม่ใช้กับประเภทนี้จาก URL ตรง → `AppShell` แสดง "แอปนี้ไม่ได้ใช้กับ{ประเภท}" + ปุ่มกลับหน้ารวมแอป
    - **ระดับเมนู:** `AppMenuItem.businessTypes` (`menuItemAvailableFor` / `menuAvailableFor`) — แอปขาย: "ขายสินค้า" (`invoices`) เฉพาะซื้อขาย / ผลิต, "ใบแจ้งหนี้" (`service-invoices`) เฉพาะบริการ / ก่อสร้าง; เปิดจาก URL ตรง → `MenuGuard` ใน `layout.tsx` ของเมนูนั้นแสดง "เมนูนี้ไม่ได้ใช้กับ{ประเภท}" + ปุ่มกลับหน้าแรกของแอป
    - ไม่รู้ประเภท (`business_type` ไม่มีใน `/me/companies/{id}`) = แสดงทุกแอป / เมนูตามสิทธิ์
- บริษัท + สิทธิ์โหลดด้วย `getCompanyContext(companyId)`: 2 คำขอพร้อมกัน ครั้งเดียวต่อ request (React `cache`) แม้ layout / page เรียกซ้ำ
  - `/me/companies/{id}` (organization) ชื่อบริษัท — สมาชิกทุกคนอ่านได้ ไม่ต้องมีสิทธิ์อ่านบริษัท
  - `/companies/{id}/access` (identity) สิทธิ์ของผู้ใช้
  - แยก 2 คำขอเพราะข้อมูลอยู่คนละ module (JOIN ข้าม module ไม่ได้ และ identity ไม่พึ่ง organization) — เรียกพร้อมกันจึงไม่เพิ่มเวลารอ
- เมนูที่ยังไม่มีหน้าจริงแสดง "หน้านี้กำลังพัฒนา"

### ประเภทธุรกิจ (`config/businessTypes.ts`, `features/companies/BusinessTypePicker.tsx`)

- 4 ประเภท: `service` ธุรกิจบริการทั่วไป, `trading` ธุรกิจซื้อขายสินค้า, `manufacturing` ธุรกิจผลิตสินค้า, `construction` ธุรกิจก่อสร้าง — ชื่อ / คำอธิบายที่ `texts.businessTypes`
- หน้าสร้างบริษัท (`/companies/new`): บังคับเลือก 1 ประเภทด้วย radio card (fieldset + legend + radio จริง — Tab เข้ากลุ่ม, ลูกศรเลื่อน, focus ring บนการ์ด) ข้อผิดพลาดอยู่ใต้กลุ่ม (`role="alert"`, `aria-describedby`)
  - ส่ง `business_type` ไปกับ `POST /companies`; backend นำเข้าผังบัญชีมาตรฐาน + ค่าตั้งต้นของประเภทนั้นตอนสร้าง
  - เปลี่ยนภายหลังไม่ได้: หน้าข้อมูลบริษัทแสดงแบบอ่านอย่างเดียว (ไม่ส่งไปกับ `PUT`)
- หน้าผังบัญชีว่าง (`DefaultChartPanel`) บอกชื่อประเภทว่าผังมาตรฐานจะเป็นชุดของประเภทไหน

### บังคับเปลี่ยนรหัสผ่าน

```text
login (รหัสชั่วคราว) → cookie มี user.must_change_password → proxy.ts พาไป /change-password?redirect=<หน้าเดิม>
  → PUT /api/session/password (Next) → backend PUT /me/password → ล้างค่าใน cookie → โหลดหน้าเดิมใหม่ทั้งหน้า
```

- ใช้ `window.location.assign` (ไม่ใช่ router) เพราะ router ของ Next จำ redirect เดิมไว้ — ต้องล้างแคช
- ช่องรหัสผ่านตั้ง `autocomplete` (current-password / new-password) และมีช่อง username ซ่อน ให้ password manager ทำงานได้
- `Toaster` อยู่ใน root layout — แจ้งผลได้ทุกหน้า (ข้ามการโหลดหน้าใหม่ด้วย sessionStorage)

- ตารางรายการในฟอร์ม: กล่องเลื่อนตารางต้อง `relative` (label ซ่อนแบบ `sr-only` เป็น absolute — ไม่งั้นทำให้ทั้งหน้าเลื่อนแนวนอนบนมือถือ)

- **ฟอร์มเอกสารขาย** (`SaleForm`, ใช้ร่วมขายสินค้า / ใบแจ้งหนี้): กรอกเอง (ลูกค้า + สาขา, ตารางสินค้า, ราคารวม VAT) หรือจากใบสั่งขาย (คงเหลือ = สั่ง − ออกเอกสารแล้ว, ใส่ 0 = ไม่ขาย); โหลดชนิดสินค้าเมื่อเลือก (1 คำขอ) เพื่อรู้ว่าต้องเลือกคลัง / กันสินค้าในใบแจ้งหนี้ค่าบริการ
  - **หักเงินมัดจำ** (`DepositsApply`): มัดจำที่รับเงินครบแล้วของลูกค้า (`/sales-deposits/open`) — ใส่ยอดก่อน VAT ไม่เกินคงเหลือ, ภาษีของมัดจำหักจากยอด ("ยอดที่ต้องชำระ")
  - ไม่มีช่องทางรับเงินในแอปขาย — หน้าดูมีป้าย "รอยืนยันรับเงิน / รับเงินแล้ว" และปุ่ม "ยืนยันรับเงินที่การเงิน" (มีสิทธิ์ `finance.receipt:post`)
- **ป้ายสถานะภาษี** (`VatBadge`): ภาษีขายเกิดแล้ว / ภาษียังไม่ถึงกำหนด / ภาษีเกิดบางส่วน (สี + ข้อความ)
- **พิมพ์ A4** (`.../print`): แผ่น `.a4-sheet` ขนาด 210×297mm บนจอเท่ากับตอนพิมพ์ (`@page a4doc` ขอบ 12mm, ช่องลงนามชิดล่าง, จอแคบย่อทั้งแผ่นด้วย zoom); ใช้ `bill_to` ที่เก็บในใบ; `PrintDocument` (หัวกระดาษจาก `GET /me/companies/{id}/letterhead`, ผู้ซื้อพร้อมเลขผู้เสียภาษี / สาขา, ตาราง, ยอดรวม, จำนวนเงินตัวอักษร `bahtText`, ช่องลงนาม) + `@page A4` ใน `app.css`
  - ชื่อเอกสาร (`salePrintTitle`): ขายสินค้า = ใบส่งของ / ใบแจ้งหนี้ / ใบกำกับภาษี (ไม่จด VAT = ใบส่งของ / ใบแจ้งหนี้); ใบแจ้งหนี้ค่าบริการ = ใบแจ้งหนี้ (หมายเหตุ "ไม่ใช่ใบกำกับภาษี"), `?as=tax-invoice` = ใบกำกับภาษี (เลขที่ / วันที่ของใบกำกับ + อ้างถึงใบแจ้งหนี้); มัดจำ = ใบรับเงินมัดจำ / ใบกำกับภาษี; ใบวางบิล = รายการใบค้าง + นัดชำระ + ผู้วางบิล / ผู้รับวางบิล
  - หักมัดจำแสดงเป็นบรรทัดติดลบในยอดรวม แล้ว "ยอดที่ต้องชำระ" (จำนวนเงินตัวอักษร = ยอดที่ต้องชำระ)
- จำนวนเงินรายบรรทัดแสดงก่อน VAT (ราคารวม VAT = แสดงตามราคาที่กรอก) ให้ตรงกับ "รวมเงิน"

### แอปการผลิต (`manufacturing/`, `features/manufacturing/`)

แสดงเฉพาะบริษัทประเภท "ธุรกิจผลิตสินค้า" (`businessTypes: ['manufacturing']`, สี `--color-app-manufacturing`)

| เมนู | หน้า | หมายเหตุ |
|---|---|---|
| ใบสั่งผลิต | รายการ (กรองสถานะ / สินค้า / `from`–`to`), สร้าง, ร่าง (แก้หัว + จำนวนวัตถุดิบที่ต้องใช้), ดู, พิมพ์ A4 | `OrderForm`: เลือกสินค้า → ดึงสูตรที่ใช้งาน (`GET /boms?item_id=&status=active`) แล้วเลือกสูตรหลักให้; คลังตั้งต้นจากค่าตั้งการผลิต |
| สูตรการผลิต | รายการ (กรองสินค้า / สถานะ), สร้าง, แก้ไข / ลบ (ไม่มีสิทธิ์ = อ่านอย่างเดียว) | `BomForm`: สินค้าที่ผลิต + จำนวนต่อรอบ, วัตถุดิบ (จำนวนต่อรอบ + % สูญเสีย 0–100, ห้ามซ้ำ / ห้ามใช้ตัวเอง), ค่าแปลงสภาพ (รายการ + บัญชีค่าใช้จ่าย + จำนวนเงินต่อรอบ), สูตรหลัก |
| รายงาน | ต้นทุนการผลิตตามใบสั่งผลิต, การใช้วัตถุดิบเทียบสูตร, งานระหว่างผลิตคงเหลือ (ณ วันที่) | `GET /reports?book=production-cost / material-usage / wip`; พิมพ์ + CSV |
| ตั้งค่า | สมุดรายวัน, บัญชีงานระหว่างผลิต, บัญชีค่าแปลงสภาพที่ปันเข้า, คลังเริ่มต้น | บัญชีใช้เฉพาะระบบ perpetual |

- หน้าใบสั่งผลิต: สถานะ ร่าง → กำลังผลิต → ผลิตเสร็จ (หรือยกเลิก); แถบปุ่ม `OrderActions` ตามสถานะและสิทธิ์ `manufacturing.order:manage`
  - ร่าง: ปล่อยผลิต (ยืนยันก่อน), ยกเลิก
  - กำลังผลิต: เบิกวัตถุดิบ, คืนวัตถุดิบ (เมื่อมีของที่ใช้จริง), ผลิตเสร็จ / รับสินค้า, ยกเลิก
  - แต่ละการกระทำเปิด "แผง" ใต้แถบปุ่ม (ไม่ใช้ modal — โฟกัสหัวแผงเมื่อเปิด, Esc / ปุ่มปิด): เบิกตั้งต้น = ยังต้องเบิก (ต้องใช้ − ใช้จริง) ห้ามเกิน, คืนห้ามเกินใช้จริง, บรรทัด 0 / ว่างไม่ส่ง; ผลิตเสร็จตั้งต้น = จำนวนสั่งผลิต (ยืนยันก่อน); ยกเลิกต้องมีเหตุผล
  - ตารางวัตถุดิบ (ต้องใช้ / เบิก / คืน / ใช้จริง / ต้นทุน + แถบความคืบหน้าขณะผลิต), การ์ดต้นทุน (วัตถุดิบ + ค่าแปลงสภาพ = รวม, ต่อหน่วยเมื่อผลิตเสร็จ), ความเคลื่อนไหว (ลิงก์เอกสารสต็อกในแอปคลัง; เลขที่รายการบัญชีว่าง = "–")
  - **ระบบบัญชีสินค้า periodic (ค่าเริ่มต้นทุกประเภทธุรกิจ):** การผลิตบันทึกเฉพาะสต็อกและต้นทุน ไม่ลงรายการบัญชี — หน้าใบสั่งผลิต / ค่าตั้งแสดงหมายเหตุนี้
- พิมพ์ "ใบสั่งผลิต / ใบเบิกวัตถุดิบ" (`orders/{id}/print`): `.a4-sheet` เดียวกับเอกสารขาย, ชื่อบริษัท, สินค้า / จำนวน / สูตร / คลัง, ตารางวัตถุดิบที่ต้องใช้ + ช่อง "จ่ายจริง" เขียนมือ, ลงนาม 3 ฝ่าย (ผู้สั่งผลิต / ผู้เบิก / คลัง)
- เลขที่ใบสั่งผลิต (`manufacturing.production_order`, คำนำหน้า MO) ตั้งได้ที่ องค์กร › เลขที่เอกสาร — ตารางจัดกลุ่มตาม module (ขาย → จัดซื้อ → คลัง → การผลิต → การเงิน → บัญชี) และใช้ชื่อไทยจาก `texts.numbering.docTypes` เมื่อมี

### ใบลดหนี้ (`features/credit-notes/`, ใช้ร่วมขาย / จัดซื้อ)
- เมนู "ใบลดหนี้" ทั้งแอปขาย (`/sales/credit-notes`) และจัดซื้อ (`/purchasing/credit-notes`) — สร้างจากหน้าใบกำกับเดิม (ปุ่ม "ออกใบลดหนี้" / "บันทึกใบลดหนี้" เมื่อยังมียอดค้าง) → `new?invoice_id=`
- `CreditNoteForm`: เลือก รับคืน / ส่งคืนสินค้า (จำนวน + ราคา ≤ ราคาเดิม, คลัง) หรือ ลดราคา (จำนวนเงินต่อบรรทัด); เหตุผลเลือกจากรายการหรือพิมพ์เอง; ตรวจเกินที่คืนได้ / เกินมูลค่าที่ลดได้ / เกินยอดค้างก่อนส่ง; จัดซื้อเพิ่มเลขที่ / วันที่ใบลดหนี้ของผู้ขาย
- หน้าดู: อ้างอิงใบกำกับเดิม, เหตุผล, (ขาย) มูลค่าเดิม / ที่ถูกต้อง / ผลต่าง, ยกเลิก; ขายพิมพ์ A4 "ใบลดหนี้ / ใบกำกับภาษี" ตาม ม.86/10
- จากใบแจ้งหนี้ค่าบริการ (`new?invoice_id=&kind=service_invoice`): ลดราคา / ส่วนลดอย่างเดียว (`allowanceOnly`); `vat_kind = undue` (ภาษียังไม่ถึงกำหนด) พิมพ์เป็น "ใบลดหนี้" (ไม่ใช่ใบกำกับภาษี, `creditNotePrintTitle`) และไม่เข้ารายงานภาษีขาย
- ใบกำกับเดิมแสดงยอดลดหนี้ (ลิงก์ไปรายการใบลดหนี้ของใบนั้น) และยอดลด / คืนต่อบรรทัด

### ภาษีปิดเดือน
- รายงานภาษีขาย (`/sales/reports?book=output-vat`) และภาษีซื้อ (`/purchasing/reports?book=input-vat`) — ใบลดหนี้เป็นยอดติดลบ, ลิงก์ไปเอกสาร
  - ภาษีขายแสดงเฉพาะเอกสารที่ภาษีเกิดแล้ว พร้อมประเภท: ขายสินค้า / รับเงินมัดจำ / ใบกำกับภาษี (บริการ) / รับเงินค่าบริการ (แสดงเลขที่ใบรับเงิน ไม่มีลิงก์) / ใบลดหนี้ และเลขที่อ้างอิง (ใบแจ้งหนี้ค่าบริการต้นทาง / ใบกำกับเดิม)
  - ภาษีขายยังไม่ถึงกำหนด (`?book=undue-output-vat&end_date=`): ใบแจ้งหนี้ค่าบริการที่ภาษียังไม่เกิด ณ วันที่ — ใช้กระทบยอดบัญชีภาษีขายยังไม่ถึงกำหนด
- สรุป ภ.พ.30 (`/finance/reports?book=vat-summary`) — ภาษีขาย / ซื้อ / ต้องชำระ / ชำระเกิน + ลิงก์ไปรายงานรายใบของช่วงเดียวกัน
- หนังสือรับรอง 50 ทวิ: ปุ่ม "พิมพ์หนังสือรับรอง 50 ทวิ" ในใบสำคัญจ่ายที่มีภาษีหัก → `/finance/payments/{id}/wht-certificate` (`WhtCertificate`: ฉบับที่ 1 / 2, ภ.ง.ด.3 / 53 ตามประเภทผู้รับเงิน, ยอดรวมตามประเภทเงินได้ของ "ประเภทภาษีหัก ณ ที่จ่าย")

### การโหลดหน้า (skeleton, `features/loading/`)
- ทุกการโหลดหน้าแสดง skeleton เสมอ (ไม่ว่าจะเร็วหรือช้า) — โครงเดียวกับหน้าจริงเพื่อไม่ให้เนื้อหากระโดด; `role="status"` + `aria-busy` + ข้อความ "กำลังโหลด..." สำหรับ screen reader; ปิด animation เมื่อตั้ง reduced motion
- `PageSkeleton kind=` `list` / `dashboard` / `report` / `form` / `doc` ใช้ใน `loading.tsx`:
  - `{app}/loading.tsx` = list (หน้ารายการทั้งหมดของแอป); `dashboard/`, `reports/` ตามชื่อ; `new/`, `settings/`, `organization/company/`, `[id]` ของทะเบียน = form; `[docId]`, `[entryId]` = doc
  - หน้าใหม่: ถ้าไม่ใช่หน้ารายการ ให้เพิ่ม `loading.tsx` ตามชนิดหน้า
- เปิดแอปในแท็บใหม่ (hard load): `AppShell` แสดงแถบแอป (ชื่อ / ไอคอนจาก appKey) + skeleton ทันทีระหว่างรอสิทธิ์ (Suspense ภายใน layout)
- หน้ารวมแอป / หน้าเลือกบริษัท: แถบบนแสดงทันที ส่วนที่รอ backend อยู่ใน Suspense (`LauncherSkeleton`, `CompaniesSkeleton`)
- ผลวัด (2026-11-23, 20 หน้า): production build กดเมนู → หน้าขึ้น 70–360 ms (backend 5–50 ms ต่อคำขอ); `next dev` ช้ากว่า 10–30 เท่า (compile ตอนเปิดหน้าครั้งแรก, ไม่ prefetch) — วัดความเร็วด้วย `npm run build && npm start` เท่านั้น
- ฟอร์มที่มีรหัสผ่าน (`LoginForm`, `ChangePasswordForm`, `MemberAddForm`) ตั้ง `method="post"` — ถ้า submit ก่อน JS โหลดเสร็จ รหัสผ่านจะไม่ไปอยู่ใน URL
